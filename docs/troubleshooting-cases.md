## 2026-07-24 · [engine·cost] 비용 게이트를 뚫고 Bedrock 호출 5배 폭증

- **증상** — Security Hub 활성 직후 Bedrock 호출이 시간당 98 → 528회.
- **원인** — ① 카탈로그 미매핑 finding이 심각도 없이 open으로 쌓여, 비용 통제용 트리아지 게이트를 88건이 그대로 통과. ② SQS `batch_size=10`인데 `maximum_batching_window`가 0이라 메시지마다 Lambda 기동(batch_size는 상한일 뿐 배치가 아님) + 조사 대상이 없어도 후속 이벤트를 무조건 발행.
- **조치** — 미매핑은 suppressed로 게이트에서 제외 · 배칭 창 30초 · 조사 대상이 있을 때만 이벤트 발행. → 엔진 기동 5분당 60 → 1회.
- **느낀점** — 트리아지 게이트는 "무엇을 조사할지"만 거른다. "얼마나 자주 깨울지"는 별개 축인데 통제가 없었다. 저볼륨일 땐 안 보이다 실 스캐너를 붙이자마자 터졌다.

## 2026-07-24 · [infra] 안전하게 잡아둔 기본값이 데모를 부숨

- **증상** — 그냥 `terraform apply`만 했는데 공격 경로가 3 → 1개로 줄고 SSO 로그인이 깨짐.
- **원인** — 타깃 앱 결함 토글(공개 S3·과도 IRSA 등)의 기본값을 안전한 쪽(false)으로 잡아둠. 데모 라이브는 의도적으로 위험한 쪽이라 `plan`이 그 차이를 드리프트로 보고 되돌림. Cognito SAML 값도 매 apply마다 null로 지워 SSO를 깼음.
- **조치** — 6개 레이어 `plan` 전수 조사 → 지뢰 3건. 레이어별 데모 기본 변수 맵 + apply가 건드리면 안 되는 값은 `lifecycle { ignore_changes }`. → 6레이어 전부 `No changes`.
- **느낀점** — "안전한 기본값"이 항상 옳지는 않다. 이 레포에선 그게 데모를 무너뜨렸다. 기본값이 "안전"이어야 하는지 "맞음"이어야 하는지는 상황이 정한다.

## 2026-07-21 · [rag] "실 지식베이스로 검색"이 사실이 아니었음

- **증상** — 콘솔엔 "RAG · 실 지식베이스 · pgvector 검색"인데, AI 챗 답변에 근거 문서가 0건.
- **원인** — `/api/system` 청크 0개. 적재 코드는 있는데 호출하는 데가 없어, destroy → 재apply 때 RDS 청크가 날아간 뒤 아무도 못 채움. 챗이 근거 없이 모델 자체 지식으로 답하고 있었음.
- **조치** — 로컬 임베딩 → SQL 적재 진입점을 코드로 고정(재apply 후 명령 1번). 청크 26개 확인 후 스크린샷 재촬영 — 빈 상태로 찍어둔 건 폐기.
- **느낀점** — 화면에 "라이브"라 적는 것과 실제 라이브는 다르다. destroy로 사라지는 데이터는 재적재 절차까지 코드로 안 남기면 조용히 빈 채로 돈다.

## 2026-07-08 · [infra·협업] 초록불인데 협업자 코드가 사라짐

- **증상** — destroy가 세션 끊김으로 중단 → 재apply 후, 협업자가 push·배포해둔 작업(분산 추적·자동 스캔)이 에러 없이 사라짐.
- **원인** — 재apply를 내 로컬 구버전 코드로 돌려 조용히 덮어씀. terraform은 초록불이라 안 드러남. 라이브 Lambda 추적 설정을 직접 조회하고서야 발견.
- **조치** — `git pull`로 협업자 커밋 병합·재빌드해 복구. destroy·재apply 전 `git fetch`로 원격에 모르는 커밋이 있는지 먼저 확인하는 절차를 규칙화.
- **느낀점** — 초록불은 "내 코드 기준 성공"이지 "최신 상태"가 아니다. 인프라 상태는 로그가 아니라 실제 리소스를 조회해서 믿어야 한다.

## 2026-07-08 · [security] 차단은 됐는데 화면엔 200

- **증상** — 플랫폼에 WAF를 붙이고 XSS 페이로드로 테스트 → curl 응답이 200 OK. 안 막힌 것처럼 보임.
- **원인** — SPA용 CloudFront 설정(403 → index.html 200)이 WAF 차단 응답까지 index.html로 바꿔치기. 상태코드만 보면 통과처럼 보였음.
- **조치** — 응답 Content-Type(JSON 아닌 HTML) + CloudWatch XSS 차단 지표로 실제 차단 확인.
- **느낀점** — 상태코드 하나만 믿으면 안 된다. 에러를 다른 것으로 바꿔주는 계층이 중간에 있으면, 그 계층이 증거까지 덮어쓴다.
